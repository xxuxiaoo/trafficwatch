# AI 连接诊断与物理绕行

进入流量中心左侧的“AI 连接诊断”。默认查看今天的故障现场；可切换真实请求、探测、路径验证、缺口与负载，再按日期、中转、Harness、网关和错误类型筛选。分页请求最多 100 条，页面每 30 秒刷新，隐藏后暂停。导出按钮导出当前筛选的当前页，不会隐含导出全部历史。

Magpie 每次尝试都单独保存，EOF 后重试成功不会覆盖失败尝试。有分阶段日志时显示 DNS / TCP / TLS / 上传 / 等待；缺字段就保持未知。后台探测只发送无凭据的 `/v1/models` 小请求，不调用模型；探测单独标记。当前活跃中转每分钟检查，其他目标每五分钟检查。没有自动节点探测或节点回退。

0.10.2 起，同一请求中反复使用同一提供方的尝试也有独立且稳定的编号。升级会通过正常签名加密队列补读当前与前一天仍存在的路由日志，并替换旧编号，不重复统计。原日志已丢失的尝试无法补造，网页和查询结果的 `quality.legacyRequests` 会说明尚未恢复的旧版记录数量。

应用日志支持 Go 的本机时间格式与带时区的 ISO 时间；发生时间和读取时间分开。启动、恢复与轮转补读只补历史，不会触发新的故障现场。无法识别时间的新行只记采集质量缺口；旧版遗留的未知时间日志标明“发生时间未知”，不作为精确日期访客卡的证据。旧现场保留，但明确提示其证据需复核。

成功的慢请求也可自动触发现场：TCP 或 TLS 超过 5 秒、发送超过 10 秒、发送后等响应首字节超过 15 秒、首段内容超过 30 秒。触发原因单独展示，不把成功请求计作连接失败；自动现场沿用合并、容量和时间上限。模型思考也可能拉长首段内容时间，因此这些阈值用于留证，不能直接判断网络根因。

独立探测使用 Windows Schannel 的 TLS 1.2，以兼容现有 .NET Framework 运行时；这不会改动 Magpie 或 Harness 的 TLS 配置。探测成功只证明该次小连接可用，不能证明真实模型请求、长连接或所有 TLS 版本都正常。探测器自身的兼容错误单独标记，不作为业务网络故障。

## 日志适配与采集完整性（0.10.3）

诊断页面新增“采集完整性”。每分钟保存一条加密自检：来源可读性、格式兼容、增量追赶、文件发现上限、解析与时间错误、TraceEvent 心跳/丢事件，以及实际 PktMon 会话归属。点击“查看自检历史”按时间回看；展开来源卡片可见处理提示。没有新请求不等于日志坏了，发现旧文件但本期没写入会显示“本期无新文件”。

| 来源 | 默认读取位置 | 提取内容 |
| --- | --- | --- |
| Magpie | `.config/magpie/routing`、本机 app.log | 每次尝试、结果、可用的分阶段耗时 |
| CC Switch | `.cc-switch/cc-switch.db` 的 `proxy_request_logs` | 仅 `data_source=proxy` 的网关请求；结果、总耗时、首字耗时及提供方标签 |
| Codex | `.codex/logs_*.sqlite`、`.codex/log/codex-tui.log` | 传输层请求结果、连接错误、明确记录的重试；忽略 SSE 正文和工具输出 |
| Claude Code | `.claude/projects` 的 JSONL、`.claude/debug` | API 错误信封、记录中的重试次数/等待及诊断错误行 |
| DSH | `.dsh/sessions` 的 JSONL / JSONL.Zstd | `llm/retry`、`llm/retry-started` 和 `turn/end` 的终止错误 |

以上位置相对于安装者的用户目录。适配只读取源文件，不开启调试、改写网关配置或调用模型。初次读取当前和前一天的可用日志/数据库条目；之后持续增量读取并长期加密保留。源文件可能包含对话，但适配器只输出诊断字段，不复制会话内容、完整 URL、原始错误文字、请求头或凭据。CC Switch 从客户端导入的会话不当成代理请求重复统计；客户端诊断行独立归为“客户端错误与重试”，不叠加到网关请求计数。

文件发现每分钟执行一次，单目录树最多检查 4096 项，每组优先读取最近 16 个本期文件；每轮最多读 8 个文件，每个 256 KiB。达到上限会显示覆盖受限，保留后续排查线索。DSH 压缩流持续解码，重启后按已提交行数补读，单次解压输出最多 16 MiB，不反复解压整个增长文件。SQLite 只读、查询限制 256 行、忙等待最多 30 毫秒。

当前时间范围还会统计请求证据：缺少 Magpie 分阶段时序、来源不提供时序、系统取证不可用、目标尚未映射、未找到同期同目标 TCP，以及缺少的重试。只有整个请求起止都在同一个授权时间窗口内，才判断重试缺项；跨日期范围不会误报。找到同一目标和时段的 TCP 是关联证据，不冒充逐个 HTTP 请求和 socket 的唯一对应。历史补读单独标注，不假装已经核验当时的系统记录。

自检记录与请求质量索引同样进入加密库，历史访客卡只看授权时间内的快照，旧日期的来源时间字段会再次裁剪。未授权的健康接口只发布功能与基础运行状态，不发布来源日志明细。

## 证据与边界

- 日志按字节续读，支持跨日、文件更换、截断和不完整行；Magpie 本机支持变更游标时一起使用，日志是断线和版本变化后的补充。
- TraceEvent 通过独立的 `TrafficWatchDiag-*` 实时 ETW 会话解码 TCP 元数据。仅保留目标地址或相关进程的连接事件，不读取 HTTPS 正文。丢事件与助手停机单独报告。
- 普通 TCP 背景为最多 30 分钟 / 64 MiB / 50,000 条的内存缓存。故障保留前 10 分钟与后 5 分钟；邻近故障合并，持续 30 分钟后拆分。每个现场最多 10,000 条证据，截断数量可见。
- PktMon 只筛选中转 IP 的 TCP/443，8 MiB 内存缓存，`--flags 0x002` 仅保留组件、计数器与筛选器摘要，禁用原始数据包内容。逐条 TCP 事件由 TraceEvent 提供。发现外部会话或筛选器会让出。故障导出时为每次停止创建独立的私有工作目录，以兼容内存模式忽略 `--file-name` 的 Windows 版本；目录仅允许安装用户、管理员和 SYSTEM。ETL 立即公钥加密后清理。存在短暂原始事件文件落盘，不能视为从未产生明文。
- 没经过 Magpie 的请求，通过可用的客户端日志和 CC Switch 请求记录补充 HTTP 错误与重试。分阶段时序仍按原来源实际提供的字段保留；源日志缺失和系统证据缺失分别显示。
- 资源记录用于关联 CPU、内存、磁盘队列、网卡计数及相关进程，相关不代表因果。

## 页面筛选

“故障与慢请求现场”的“触发原因”按现场内真正触发取证的记录匹配，包含网络故障、连接 / TLS / 发送 / 响应 / 首段内容较慢。中转、客户端、网关与原因必须同时属于同一条触发记录；成功请求的慢请求原因不会改变它原来的“成功”结果。切换记录类型会显示对应的类别，并清除不适用的选择。

下拉选项来自所选时间内的全部可访问记录，不受当前页或当前中转筛选限制。修改条件后点击“应用筛选”才更新结果；自动刷新使用已生效的条件。相对时间在首页刷新时推进，翻页保持同一次查询的时间边界。“重置”回到今天的全部故障与慢请求现场。页面分别显示筛选匹配条数和按中转 / 客户端 / 网关统计的时段请求次数，后者不受记录类型或错误类别限制。

首次升级时会分批补齐加密库内的旧记录筛选索引，完成前显示提示并自动继续，原始历史保留。日期受限的 AI 卡只能用授权日期内、发生时间可确认的触发项进行匹配和生成选项，现场详情也遵守查询时段。

## 加密与 AI

新增记录不复用明文日志文件。后台使用原密码库公钥与采集签名密钥，进入独立的密文队列；解锁后导入独立的 SQLite3MultipleCiphers ChaCha20-Poly1305 加密诊断库。全部摘要、明细与索引在加密库中。高频背景仅驻内存，诊断摘要、故障现场及附件无限保留。原两路流量记录的无限保留策略不变。

AI 卡必须单独勾选“AI 连接诊断”。仅有本机或梯子范围的旧卡不能读诊断。日期、操作、有效期、锁屏继续与撤销沿用原机制；现场内的每条证据再次过滤日期。只读卡不能标记现场或导出。CLI：`TrafficWatch-AI.cmd diagnostics --from <毫秒时间戳> --to <毫秒时间戳> --kind incident`，分页用返回的 `next` 作为 JSON `--cursor`；可按 `--category`、`--provider`、`--harness`、`--gateway` 筛选。不要把密码给 AI。

## 物理绕行

安装者明确配置 RelayHosts 与 BypassProfileScript 后，后台动态发现物理 IPv4 网卡，从绑定该接口的 DNS 查询得到 A 地址。先添加精确 `/32` 路由，再更新带标记的 hosts 区块和订阅脚本增强。按 TTL 刷新，旧地址有 15 分钟宽限期。只使用已验证的物理接口，不自动切节点。当前 IPv6 辅助尚不部署 `/128`，没有可用物理 IPv6 时以实际 IPv4 验证为准；接口或 IPv6 拓扑变化应重新验收。

“已验证”同时要求系统解析为真实地址、Find-NetRoute 选择物理源地址、绑定接口的小连接成功拿到物理源地址，以及连接存活时 Clash 对应四元组不存在。辅助每分钟复查路由，每 15 分钟、换网卡后重新验证连接。地址失效或 DNS 失败会标为需复查，不得拿昨天的验证当成今天的保证。共享同一 IP 的其他域名也可能遵循该 IP 路由。

桌面和托盘支持单独启停诊断、启用绕行、恢复原 Clash DIRECT 路径。停止诊断不改变路由；“完全停止全部”停止采集、诊断与绕行维护进程，但最后发布的路由仍存在，需点“恢复 Clash DIRECT”撤回。撤回只移除本项目受管的 hosts 区块、创建的路由与标记脚本，保留原 DIRECT 规则及其他用户配置。发现受管 hosts 区块被用户修改时停止覆盖并报告冲突。

启动依靠现有 SYSTEM 开机守护，Windows 锁屏不影响加密采集。程序异常不会作为业务转发链的一环阻断请求。
